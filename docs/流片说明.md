# to2610-switch 流片说明

流片说明报告（docx）的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

八口 100 Mbps 以太网交换芯片，面向 ECOS 2610 班车。片上没有处理器：复位一放开就按学习到的地址转发，焊上板子、接上八颗 PHY 就是一台八口交换机；接了管理主机，才用得上端口开关、端口隔离、查表与计数。

它由息壤从组织的 IP 库装配而成，没有一行自有 RTL：`eswitch` 是交换核心（八口、16 条学习表、端口隔离），`spis` 是 SPI 从口，片外主机经它读写片上总线，`gpio` 给出六根通用管脚，其中两根拨 MDIO 管 PHY。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 端口 | 8 个 RMII 口 | 每口接一颗片外 RMII PHY，片上不含 PHY |
| 速率与双工 | 100 Mbps 全双工 | RMII 每拍收发 2 位，参考时钟 50 MHz。不支持 10 Mbps，也不支持半双工（没有冲突检测） |
| 转发方式 | 直通 | 收齐目的与源两个地址（12 字节，100 Mbps 下 0.96 µs）就定去向，不等整帧；转出的帧与收到的逐字节相同，FCS 原样带着 |
| 帧长 | 不设上限 | 长度不进判据，测到 1514 字节加 FCS 的最长标准帧；短于 12 字节、地址都没收齐的残帧丢掉 |
| 地址学习 | 16 条，全相联 | 只学单播源地址（802.1D 7.8）；同一地址换了口就原地更新；表满时轮换覆盖 |
| 老化 | 10 至 1,000,000 秒，默认 300 | 照 802.1Q 8.8.3，每条记最后一次学到它的秒数，过期即删 |
| 未知单播、广播、组播 | 泛洪 | 发往除入口外所有开着、未被隔离的口 |
| 本口过滤 | 有 | 目的地址学在入口那个口上（经集线器接在同一口的两台设备）的帧不转出（802.1D 7.7） |
| 端口开关 | 每口一位 | 关着的口不转发它收到的，也收不到别人的；收不收在帧头定下，帧中途开关不会截出半帧 |
| 端口隔离 | 每个入口一张出口屏蔽表 | 分出互不相通的广播域，例如 0 至 3 口与 4 至 7 口。这是按端口分的 VLAN，不认 802.1Q 标签 |
| 出口冲突 | 整帧丢并计数 | 一个出口同一时刻只归一个帧；另一帧同时要这个出口，就在这个出口上整帧丢掉，不排队、不交错 |
| 坏帧 | 照转 | FCS 到帧尾才知道，直通时帧已发出；收端按 FCS 丢掉 |
| 计数 | 每口三个 32 位计数器 | 收到的帧、转出的帧、因出口被占丢掉的帧 |
| 查表 | 逐条读出 | 每条的地址、所在口与是否有效 |
| 管理口 | SPI 从口，模式 0 | SCK 不超过主频的八分之一，即 6.25 MHz；可读写片上任意地址；不接也能用 |
| 通用管脚 | 6 根，逐根设方向 | 0、1 两根拨 MDC、MDIO 管理 PHY，其余 4 根空余 |
| 复位默认 | 全开 | 每口开着、学习开着、不隔离，上电即转发 |

### 转发过程

每个口收到的字节先进入口缓冲（64 字节）。收齐两个地址时同时做两件事：源地址是单播就交给学习表，目的地址去查表，查到就只发那一个口，查不到就泛洪；结果再与端口开关、隔离表相与，并去掉入口本身。裁决器每拍按轮转挑一个入口，只把此刻空闲的出口授给它，授出的出口归这一帧直到帧尾。之后入口缓冲从头放出这一帧，出口补上前导码与帧起始符发出，帧间隔 96 位时间。

### 管理口协议

SPI 模式 0（CPOL 0、CPHA 0），高位先出，`CS_N` 低有效。地址与数据都是 4 字节大端，地址低 2 位不看。

| 命令 | 主机发 | 芯片回 |
|:--:|:--:|:--:|
| 0x02 写 | 4 字节地址，再每字 4 字节数据 | 无；每收满一字写一次，地址加 4 |
| 0x03 读一字 | 4 字节地址，1 个空字节 | 4 字节数据 |
| 0x0B 连读 n + 1 字 | 4 字节地址，1 字节 n，1 个空字节 | 每字 4 字节 |
| 0x05 状态 | 1 字节 | 第 0 位：总线回了错；第 1 位：主机快过总线。读一次即清 |
| 0x9F 标识 | 4 字节 | 53 50 49 53，即「SPIS」 |

读只取命令要的那几个字，不预取：有的寄存器读了有副作用。`CS_N` 拉高即结束，可停在任一字节。

### 主机端工具

`sw/spis.py` 是上面的协议，`sw/switch.py` 是寄存器地址与常用操作，经 USB 转 SPI（FT232H）或树莓派的 spidev 连芯片。整片测试也经这两个文件管芯片，所以上板用的就是测过的那份。

| 命令 | 做什么 |
|:--:|:--:|
| boot | 把「一秒」改成本片主频的拍数，老化按真秒走 |
| ident | 读管理口标识 |
| table | 列出学到的地址与所在口 |
| counters | 列出每口的收、发、丢帧数 |
| isolate 0-3,4-7 | 分广播域；给空串即全通 |
| mdio 物理地址 寄存器 [值] | 经 GPIO 读或写一颗 PHY 的寄存器 |

## 寄存器

地址、位宽与复位值由报告按 `eswitch` 与 `gpio` 的 `regmap.yaml` 和本仓 `ip.yaml` 的基地址生成，这里只写含义。

| 寄存器 | 含义 |
|:--:|:--:|
| ctrl | en 为总开关；learn 为学习开关；flush 置 1 期间学习表一直清空，用完写回 0 |
| porten | 每口一位，1 为开 |
| linkup | 本版等于 porten：没有接 PHY 的链路状态线 |
| agetime | 老化时间，单位秒 |
| tick | 一秒的时钟拍数减一。复位按 100 MHz，本片 50 MHz 要写 49,999,999，boot 会写 |
| maclo | 学习表第 i 条地址的低 32 位 |
| machi | 第 31 位为有效，第 23 至 16 位为所在口，低 16 位为地址的高 16 位 |
| rxcnt | 每口收到的帧数，关着的口不计 |
| txcnt | 每口转出的帧数 |
| drops | 每个入口的帧里，要去的出口有被占着的，每帧记一次 |
| isol | 第 p 项里置 1 的出口，不许从 p 号口转发过去 |
| dout | 每根管脚的输出值 |
| din | 每根管脚当前的输入电平 |
| dir | 每根一位，1 为驱出，0 为输入 |

## 板级连接

| payload 位 | 信号 | 接到 |
|:--:|:--:|:--:|
| 7p 至 7p+2 | 口 p 的 TXD[1:0]、TX_EN | PHY p 的 RMII 发送脚 |
| 7p+3 至 7p+6 | 口 p 的 RXD[1:0]、CRS_DV、RX_ER | PHY p 的 RMII 接收脚 |
| 56、57、58 | SCK、CS_N、MOSI | 管理主机，SPI 模式 0 |
| 59 | MISO | 管理主机；只在 CS_N 为低时驱动 |
| 60、61 | GPIO 0、1 | 各 PHY 的 MDC、MDIO，由主机端脚本经 GPIO 拨出 |
| 62 至 65 | GPIO 2 至 5 | 空余：PHY 复位、指示灯、拨码 |

p 取 0 至 7，所以 0 号口占第 0 至 6 位，7 号口占第 49 至 55 位。payload 第 n 位是 MPC-Frame 的 `user_io[n + 7]`；逐位的完整位表在报告的「payload 位表」里。

- 时钟 50 MHz，必须与八颗 PHY 的 RMII `REF_CLK` 同源：一颗晶振经扇出缓冲同时给芯片与各 PHY，PHY 设成参考时钟输入。
- PHY：任意 RMII 100 Mbps PHY，每口一颗，配带变压器的水晶头。自协商全开时，对端支持 100 Mbps 全双工就协商到它。对端只支持 10 Mbps 时不能用，只支持半双工时不保证；要限定，经 MDIO 把 PHY 的 4 号寄存器改成只通告 100 Mbps 全双工并重启自协商。
- MDIO：八颗 PHY 共用一条 MDIO，地址拨码要互不相同，MDIO 线要上拉。
- 复位：按住复位时全部 payload 脚高阻。每口的 TX_EN 在板上留一颗 10 kΩ 下拉，PHY 才不会在这段时间把悬空的脚当成在发送。
- 管理口可不接：USB 转 SPI（FT232H）或树莓派接第 56 至 59 位，SCK 不超过 6.25 MHz。

复位后每口都开着、学习开着。老化时间 300「秒」按 100 MHz 数，在 50 MHz 下是 600 秒；主机跑一次 `sw/switch.py boot` 就按真秒走。

## 测试说明

| 用例 | 验证什么 |
|:--:|:--:|
| boots_forwarding | 不碰管理口：复位之后两对主机直接互 ping 通 |
| management | 读标识、boot、读回；访问没有东西的地址回错，状态字记下并读一次就清 |
| flood_learn_forward | 广播逐字节原样泛洪到其余七口、不回入口；源地址学进表；发往它的单播只走那一个口 |
| ping_pairs | 四对主机同时互 ping；同时发的 ARP 广播互相占着出口，靠 ARP 重发走通 |
| vlan | 分成两个隔离组：组内互通，跨组不通，撤掉隔离又通 |
| ageing | 学到的地址过了老化时间就没了，发给它的单播重新泛洪 |
| contention | 两个口同一拍发往同一个口：一帧完整送到，另一帧整帧丢掉并记在 drops 上，不交错成坏帧 |
| port_disable | 关掉的口既不转发它收到的，也收不到别人的 |
| long_frame | 1514 字节加 FCS 的最长标准帧泛洪到其余七口，逐字节相同 |
| same_port | 目的地址学在入口那个口上：帧哪个口都不出 |
| table_full | 一个口上灌进 20 个源地址：表项不超过 16 条，最早的四个被轮换顶掉、其余都在；发往最新地址的单播只走它的口，发往被顶掉地址的泛洪 |
| counters | 每口的收、发帧数 |
| mdio | 经 GPIO 拨出 MDIO：读 PHY 的标识寄存器，写一个再读回，没有 PHY 的地址读出全 1 |
| gpio | 余下的四根 GPIO 当输出时驱到焊盘上，当输入时读得回外面给的电平 |

全部用例跑在交付的那份 `.v` 上，经五口顶层进出；管理走 `sw/` 里上板用的同一份代码。

## 局限

直通而没有整帧缓冲：出口正忙时来的帧在那个出口上丢掉并计数，不排队。两台主机长时间满速发往同一个口会丢帧，TCP 与 ARP 靠重传恢复。只有 100 Mbps 全双工；没有 802.1Q 标签，只有端口隔离；链路状态不读 PHY。学习表 32 条，64 条时 CAM 的落位在 bsc 里平方级展开、编不动，要先改 `hwcore` 的 `Cam`。
